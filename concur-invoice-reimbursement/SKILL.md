# Concur 发票报销自动化

根据出差文件夹中的发票 PDF,在 SAP Concur 上完成报销单创建、逐笔费用录入、明细分摊和发票上传。

## 前置准备

### 1. 确认发票文件夹与分类

`LS` 列出用户指定文件夹(默认 `<发票根目录>/<城市 日期>/`),按文件名和内容分类:

| 发票特征 | 归类 |
|---------|------|
| `{出发地}-{目的地} Invoice.pdf` / `Itinerary.pdf`(BCD Travel 开具) | 机票 |
| `Hotel invoice.pdf` + 水单 | 酒店 |
| `滴滴电子发票.pdf` + `滴滴包车行程单.pdf` | 滴滴包车 |
| `滴滴电子发票A/B.pdf` + `滴滴出行行程报销单A/B.pdf` | 滴滴地面交通 |
| 餐饮发票(图片或 PDF) | 餐饮 |

用 `pdftotext <file> -` 提取关键字段,避免 `Read` 读取大 PDF 超限:
发票号码、开票日期、价税合计(报销金额取此值)、乘机/入住日期、票号、航班号。

### 2. 登录

导航到 SSO 登录页:

```
<企业 SSO 登录入口，由用户提供>
```

**必须由用户人工登录**。用 `browser_waiting_for_user_interaction` 交出浏览器控制权,等待用户确认后再继续。登录成功后经 OnePortal「员工报销」跳转到 Concur(`<企业 Concur 域名>`)。

会话超时时,重新走上面的 SSO 链接让用户登录。

## 报销单抬头

新建报销单后依次填写(逐项向用户确认,不要自行假设):

- **报告名称**:`城市 + 主题`,例如「长沙会议」「烟台市场走访」
- **报告政策**:<适用的公司费用政策>
- **业务理由**:与报告名称一致,例如「参加/举行培训/会议」
- **报告日期**:默认当天
- **备注**:通常留空

## 费用类型映射

| 费用类型 | expenseTypeId | 适用发票 |
|---------|---------------|---------|
| 飞机票价 | <机票类型ID> | BCD 机票发票 + 行程单 |
| 房费和税费 | <酒店类型ID> | 酒店发票 + 水单 |
| 租车费 | <租车类型ID> | 滴滴包车 |
| 地面交通 | <地面交通类型ID> | 滴滴快车/专车等其余用车 |
| 内部人员餐费(公司内) | — | 餐饮(按公司政策确认) |

入口:报销单页「添加费用」→「手动创建费用」→ 搜索费用类型;
或直接访问 `.../expenses/new?expenseTypeId=<id>`。

## 通用填写规则

所有费用共通的字段填法:

- **交易日期**:统一用开票日期。**必须用日历图标点击选择**,直接键入文本即使输入框显示了值,React state 也可能未提交(表现为保存报错「必须提供有效信息:交易日期」)。✅ 少数表单(如机票、房费和税费)键入 `YYYY-MM-DD` + `Enter` 可生效;失败就改用日历。
- **付款类型**:`现金支出费用`
- **币种**:默认 `CNY`
- **收据状态**:必填 `Receipt`,否则保存失败
- **城市**:点开城市下拉 → 弹出搜索框输入城市名(如 `Changsha`)→ 选 `Changsha, Hunan`
- **业务理由**:下拉直选,与报销单主题一致
- **金额**:取发票「价税合计」含税总价

### 日历选择器(JS 兜底)

日历面板不在无障碍树中,用 `browser_evaluate` 操作:

```javascript
// 翻到目标月份
document.querySelector('[aria-label="上个月"]')?.click();
// 点击日期单元格(遍历 td / [role=gridcell] 按文本匹配)
Array.from(document.querySelectorAll('td,[role=gridcell]')).find(el => el.textContent.trim() === '13')?.click();
```

选完按 `Enter` 确认。选完日期后**回读字段确认夜数/值已变成实际数字**(如酒店夜数应为 2 而不是 0)。

### 保存要点

- 页面常有**两个「保存费用」按钮**(顶部工具栏一个、表单底部一个)。底部按钮可能无效,优先点顶部那个(快照中 ref 更靠前的)。
- 保存后 URL 应跳回报销单列表页 `.../reports/<id>`;没跳转就说明有校验错误。
- 排查错误:读 `document.body.innerText` 找「错误」段,会明确指出缺哪个必填项。常见原因:付款类型被页面截断未填、交易日期未真正提交、收据状态未选。
- 页面字段被折叠时先点「显示更多」,或滚动后再填,避免漏填导致「必填」错误。

## 分类流程

### 机票(飞机票价)

- 交易日期 = 乘机日期(BCD 发票 DueDate 字段)
- 航班类型:点 combobox 直选「国内」/「国际」
- 出发地 / 目的地:点「搜索XX的筛选器选项」→「按代码搜索」输入机场码(`SHA` / `CSX`)→ 点 option
- 卖方:直接键入 `China Eastern Airlines` 等航司名(列表无此选项,是自由文本)
- 城市:同上通用规则
- 票号 = 发票 `Ticket number`;发票号 = `Invoice NO.`
- 金额 = `TotalAmount`;服务等级 = `经济舱`
- 收据:**两张** —— 发票(`X-Y Invoice.pdf`)+ 行程单(`X-Y Itinerary.pdf`)

### 酒店(房费和税费)

- **日期范围只能通过日历图标点击选定**:打开日历 → 点开始日期 → 点结束日期,夜数自动计算(如 7.20→7.22 = 2 晚)。直接键入文本夜数会保持 0 且保存失败。
- 交易日期 = 开票日期;卖方 = 酒店英文名(如 `Sheraton Changsha Hotel`,自由文本)
- 金额 = 发票价税合计
- **明细(Itemization)必填**:
  1. 保存费用后点「明细」tab → 自动弹出「添加明细」
  2. 保持默认「相同每日金额」(= 每晚金额)
  3. **单晚金额 = 总价 ÷ 夜数**(如房价 1132.08 ÷ 2 = 566.04,税 67.92 ÷ 2 = 33.96)。若填单价总额会翻倍出现「已分列明细超出」错误
  4. 汇总栏显示「剩余 CNY 0.00」即平衡
  5. 点**顶部**的「保存明细」,等「正在保存」消失,URL 变为 `.../itemizations`;明细条数 = 夜数 × 2(房价行 + 税行,税行显示为「酒店传真费」属正常)
- 收据:**两张** —— `Hotel invoice.pdf` + `Hotel 水单.pdf`

### 滴滴包车(租车费)

- 租车天数 = `1`;汽车等级按车型选(5 人车型选「紧凑」)
- 卖方 = `Didi Chuxing`;交易日期 = 开票日期
- 金额 = 价税合计
- 收据:**两张** —— `滴滴电子发票.pdf` + `滴滴包车行程单.pdf`

### 滴滴地面交通(地面交通)

- 费用定义(新增字段):点开下拉 → 选 `的士`(网约车);其余选项:公交/地铁/火车/轮渡/Car Service
- 卖方名称 = `Didi Chuxing`(文本框,非下拉)
- 交易日期 = 开票日期(**此表单键入易失败,用日历选择更稳**)
- 金额 = 每张发票的价税合计
- 收据:**两张** —— 对应电子发票 + 对应行程单(A 配 A,B 配 B,不要交叉)

## 发票上传(关键技巧)

`browser_upload_file` 无法定位 Concur 的隐藏 `input[type=file]`,按以下步骤:

1. **打开发票窗口**:费用行点「查看发票」,或明细页工具栏「查看发票」→ 弹窗显示「上载或拖放发票到此处」
2. **注入自定义输入框**(`browser_evaluate`):

```javascript
document.body.insertAdjacentHTML('beforeend',
  '<input type=file id=trae-upload-input multiple aria-label=TraeUploadInput style=position:fixed;top:10px;left:10px;z-index:99999>');
```

3. 快照找到 `TraeUploadInput` 的 ref,逐份 `browser_upload_file(ref, filePath)`;每传一份立即存下来(第二次上传会覆盖 `files[0]`):

```javascript
window.__f1 = document.getElementById('trae-upload-input').files[0];  // 发票
window.__f2 = document.getElementById('trae-upload-input').files[0];  // 行程单/水单
```

4. **一起派发**到 Concur 的隐藏输入框(注意 `dt.items.add` 不可漏,空 DataTransfer 派发无效):

```javascript
((dt, els) => {
  dt.items.add(window.__f1); dt.items.add(window.__f2);
  els.forEach(el => { el.files = dt.files; el.dispatchEvent(new Event('change', {bubbles:true})); });
  return 'done';
})(new DataTransfer(), Array.from(document.querySelectorAll('input[type=file]')).filter(el => el.id !== 'trae-upload-input'))
```

5. 等待 5–10 秒「正在加载发票图像」消失,文件进入**可用发票池**。验证:弹窗内点「从可用发票中选择」,能看到新文件名和「已上载: <时间>」即成功
6. **附加并合并**:
   - 点该发票卡片的「附加」→ 第一份自动附到费用
   - 在发票窗口点「添加发票」→ 回到可用发票池 → 找第二份文件卡片点「添加」
   - 两份合并成一张多页收据,费用行显示 `查看发票 <发票文件名>`,`附加发票`按钮消失、无「缺失收据」警告即成功

要点:两张文件必须落在**同一张费用收据**里;若找不到「添加发票」入口,先关弹窗保存费用,再重开该费用明细 →「查看发票」→「添加发票」。

## 打开费用明细

- 直接点击费用列表中该条记录的蓝色区域即可打开明细;
- 或勾选该行 checkbox → 工具栏「编辑」按钮。
- 明细 URL 形如 `.../reports/<reportId>/expenses/<expenseId>`。

## 完成与核对

逐笔完成后核对:
- 报销单总额 = 各发票价税合计之和
- 每笔费用行都有「查看发票 xxx」按钮,无缺失收据警告
- 酒店费用行有「明细」摘要且金额平衡
- 剩余警告若仅为 VAT 政策提示(信息性),可以忽略

最后向用户汇报:费用笔数、各笔类型/金额/日期、总额,以及仍未处理的发票。

## 注意事项

- 每一笔费用录入前,把**从发票提取的字段值列给用户确认**,特别是卖方名称、城市、汽车/服务等级、费用类型归属——这些含业务判断,不要自行决定。
- 日期一律使用**开票日期**(机票交易日期例外,用乘机日期)。
- 非机票类发票**保持原始文件名**上传;机票文件必须按 `{出发地}-{目的地} Invoice.pdf` / `Itinerary.pdf` 命名。
- 机票类费用上传时**先传发票,再传行程单**。
- 登录、验证码等必须由用户操作,不要尝试绕过。
- 会话超时(~30 分钟无操作)会导致页面失效,重新登录后需重新核对已录费用是否保存成功。
